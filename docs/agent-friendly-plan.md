# Agent-friendly architecture plan

Date: 2026-10-17. Branch: `claude/agent-friendly-architecture-v3hihi`.

This plan rearchitects the repo so that an agent that sees one file and copies the nearest example still produces a correct change for the whole repo. Effort follows the inverse pyramid: structure first, then checks, then prose, and human review last. Every claim below is labeled measured, reproduced, or blocked.

## 3. What was prototyped and proven in this branch

- `plugin.source.json` is the only hand-edited manifest. `python3 scripts/manifests.py generate` rewrites all seven derived files byte-for-byte; `check` exits 1 and prints the fix.
- Drift resolved to one value per field: dual license, 7 keywords, root description, author url, version 0.1.0.
- `tests/test_manifests.py` (6 tests). One restores the real pre-fix marketplace file from git and asserts `check` rejects it. One hand-edits the codex license back to `MIT` and asserts `check` names the file.
- CI runs `manifests.py check` and the official validator via `npx -y @anthropic-ai/claude-code@latest plugin validate .` on every PR and push. Both commands were run locally with the same invocation.
- `verify.sh` passed all six checks locally. The MCP handshake returned `tools/list` from the real `legalize-mcp` launched through `uvx`.
- `AGENTS.md` holds the rule table (rule → enforcement). `CLAUDE.md` is a symlink to it, so there is one instruction file.

## 4. Proposed next steps, in pyramid order

1. **Structure.** Generate the README's install matrix and structure tree from `plugin.source.json` and the git tree, or delete the tree block. Decide after a prototype: if the generator is under 40 lines, keep it.
2. **Structure.** Move `skills/legalize-kr/agents/openai.yaml` interface strings into `plugin.source.json` next to `codex_interface`, since both describe the same plugin to OpenAI-family hosts. Blocked on confirming the Codex loader tolerates a generated file there.
3. **Checks.** Add an install-time smoke in CI: `claude --plugin-dir . -p "..."` is not possible without auth, so instead parse the marketplace with the same loader Claude Code uses once that is importable. Until then the 7d933f6 test is the guard.
4. **Checks.** Pin `legalize-cli` version in the MCP handshake test so a server regression upstream does not read as a repo regression.
5. **Prose.** Keep `AGENTS.md` under one screen. Every new row needs an enforcer or a reason it cannot have one.
6. **Human review.** Review only `plugin.source.json` diffs and generator changes. Generated files are noise in review; consider marking them `linguist-generated` in `.gitattributes`.

## 5. Open questions answered by prototyping rather than deferred

- Can the root `plugin.json` be the source instead of a new file? Tested: it would need harness-specific fields (`codex_interface`, marketplace owner, tags) that unknown consumers might reject. A separate source file costs one file and removes that risk.
- Does `claude plugin validate` accept generated output? Yes, zero warnings after adding `version`.
- Does the MCP command in `.mcp.json` actually start? Yes, see `features/mcp.md`.
